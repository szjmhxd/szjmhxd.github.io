一次把「死站」变成「活站」的完整过程记录
周期：2026-10-16 ~ 2026-10-23 ｜ 仓库：szjmhxd 名下 ｜ 域名：blog.szjmhxd.online

一、起点：一个只有编译产物的旧站

原 szjmhxd.github.io 有 61 篇文章，但只有编译后的 HTML、没有 hexo 源码——_config.yml、source/ 全部缺失，无法重新生成。内容构成：

  • 60 篇 2022 年”狂神说Java”视频转录笔记（预科→多态止步，非原创）
  • 1 篇原创《使用Docker部署RustDesk服务器》（2025-12-23）
  • 1 处重复：「逻辑运算符、位运算符」出现两次
  • 旁边的 blog-hexo-Melody-old（1366 文件）是同套内容旧版 + 收款码隐私图

用户工作方式（本项目沉淀的规则）：先盘点给清单 → 用户拍板 → 才动手；方案会多次改道，新指令一到旧方案立即作废。

二、三次改道，最终形态

阶段 方案 结局
① 逐篇留删 保留有用、删掉没用的 61 篇 被改道
② 整仓归档+同名新建 旧仓改名 blog-hexo-butterfly-old(private)，同名新建 public 仓做自托管 22 篇手工站上线，被改道
③ 终版三仓库分工 见下表 ✅ 至今沿用

最终三仓库分工：

仓库 性质 本地目录 职责
blog-hexo-Melody-old public —（仓库操作） 全量文章库 123 篇（原始文章的”保险库”）
blog-hexo-butterfly-old private E:\test\hexo hexo 源码工程，写文章的地方
szjmhxd.github.io public E:\test\site-new Pages 部署仓（生成产物）

三、用了什么（技术栈与工具）

环境

  • hexo 8.1.2 + hexo-butterfly 5.7.0，pnpm 管理（.npmrc 必须 shamefully-hoist=true + npmmirror，否则 butterfly 连环报 Cannot find module hexo-util → 页面静默跳过；npm 装 starter 会报 edgesOut null，必须 pnpm）
  • 本机无 Docker，用全局 hexo-cli（npm i -g）+ hexo server -p 4000 本地预览（启动须 cmd /c 包装，PS 直接 Start-Process hexo 垫片报”不是有效 Win32 应用”）
  • 云/NAS 部署：bloodstar/hexo 容器（7800→4000）或本仓 Dockerfile 两阶段构建（node→nginx，8080→80）

关键插件

插件 作用
hexo-abbrlink 短链 /posts/a4aa3bb4/（crc32+hex）；不要用 hexo-abbrlink2（生成 1/2/3 数字序号）
hexo-generator-alias 旧日期 URL 生成 meta-refresh 跳转页，旧链不 404
hexo-filter-mermaid-diagrams + butterfly 自带 mermaid 流程图渲染（需同时开 enable + code_write）

图片与素材工具链

  • Simple Icons 官方品牌图标：raw.githubusercontent.com/simple-icons/simple-icons/develop/icons/<slug>.svg（cdn.simpleicons.org 会 403）；已缓存 docker/laravel/ubuntu/deepseek/rustdesk/1panel/hexo 到 E:\test\brand-icons\
  • Pillow（Python）：webp→png、Logo 抠图/转 favicon 多尺寸、大图压缩（4K PNG 9.6MB → 1920 JPEG 262KB，省 97%）
  • Chrome headless：--headless --screenshot 渲染 SVG/网页做视觉目检
  • 掘金文章迁移：web_fetch 直接抓正文（无需浏览器插件），带 User-Agent+Referer 下载 CDN 签名图

四、定下的规范

1. 文章结构（三层独立图）

  • 正文示意图用 {% asset_img 文件名 说明 %}（纯 ![](x.png) 会生成根路径 404）
  • 素材与 md 放同名 post_asset_folder 目录

2. 封面/横幅生成规范（定稿 · 2026-10-23 晚）

经 6 轮目检微调（4f7a2ba → 6a7dd64）后固化的坐标。新文章照抄本节数值即可，不要再凭感觉起步。

封面和横幅是两张独立图片，不是同一张图的两个尺寸。两者共用配色/图标/文案，但布局各自独立计算。

A. 封面（首页卡片）630×487

  • 卡片容器约 348×269，比例 ≈ 1.294；630×487 是同比例，避免 object-fit: cover 裁掉边角
元素 参数
主图标 x=265, y=92, size=175
副图标 x=448, y=180, size=95（主图标右下方 45°，轻微相接）
标题竖条 rect x=58 y=288 w=6 h=58 rx=3
主标题 text x=82 y=332 font-size=46 bold #fff
副标题 text x=84 y=378 font-size=23 accent 色

约束：标题区从 y=288 起；图标最低点 ≈ y=275，不得越过 288。

B. 横幅（文章页顶）1600×400

  • butterfly 的 #page-header.post-bg 高度 400px、background-size: cover
元素 参数
主图标 x=1110, y=100, size=185
副图标 x=1250, y=220, size=100
标题竖条 rect x=130 y=116 w=6 h=58
主标题 text x=158 y=160 font-size=44
副标题 text x=160 y=204 font-size=20
装饰线 line x1=130 y1=252 x2=660 y2=252，stroke 透明度 0.25

约束：图标压在右侧上半部（y≈100~320），文章标题由主题压底部 ~100px 区域，两者互不重叠。

C. 迭代规则（这条是踩出来的）

  • 位置调整一次只走 ±30px 量级，且封面与横幅必须分开调：本轮封面下移 30px、横幅下移 38px，用户判定横幅过了，于是横幅单独回退 38px、封面保留 —— 绑定调整会一起返工
  • 目检顺序：先看封面（首页缩略图权重最高），再看横幅
  • 调完重新跑生成脚本，不要手改 SVG（手改会在下次批量生成时被覆盖，且容易漏改）
  • SVG 必须转义 & < >，写完用 [xml] 强转校验；同坐标两段文字至少差 24px 防重叠

D. 图标选取规则

  • 主图标 = 文章主题的官方矢量（Simple Icons 品牌图标，或用户提供的官方 SVG）

  • 副图标 = 用户最近一次给的「个性化」图标（个性化.svg 魔法棒），语义是”改造 / 美化 / 自定义”

  • 已用完的组合示例：Win11 美化 = Win11 徽标 + 魔法棒；Win10 CBS = Win10 徽标 + 刷新箭头；本篇复盘 = Hexo 官方图标 + 魔法棒（主题就是”用 Hexo 重建博客”这件事本身）

  • 品牌 logo 永远下载官方矢量，不要手绘（用户明确纠正过）

  • 生成脚本：E:\test\gen-brand-v9.js（改 themes 对象批量出图，SVG 轻量 2–3KB）；本篇用同一套 renderIcon / makeCover / makeBanner 函数单独出图

3. 部署流程

手动等价：hexo clean && generate → 复制 public\* 到 E:\test\site-new → 两仓各自 commit/push（HTTP/1.1 + postBuffer，github:443 常断需 2-8 次重试）。

4. 站点级功能

功能 实现
动态 host 版权链接 source/js/dynamic-post-link.js + inject.bottom——从 127/IP/域名访问，文章链接自动显示对应 host
占位首页 _posts 为空时 source/index.md(layout:false) 顶替；有文章时生成器自动覆盖
头像/favicon 用户书法字标（原图 RGBA 透明底黑色笔画，直接复用 alpha，勿反相）
域名 _config.yml 的 url: 是唯一配置点，改一处全站绝对链接跟着变；trailing_index:false 去掉 index.html

5. 隐私红线

  • 找用户图片只读明确给的路径；聊天附件在 .dsh\attachments\v1\objects\<hash前2位>\<sha256>
  • 曾误开用户身份证图，立即停止、不记细节
  • Melody-old 收款码：HEAD 已删但 git 历史仍在且 public（用户说”不管了”，仍挂待办）

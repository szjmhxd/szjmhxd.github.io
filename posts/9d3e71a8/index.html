中文数字四位一断：做个浮窗，复制数字就显示万进分组与金额大写

先说结论

写了一个常驻后台的 AutoHotkey 脚本：复制任意数字，光标旁弹出一张卡片，三行内容——

第一行是位段单位，第二行是万进分组的数字，第三行是中文金额大写。点一下关闭，8 秒自动消失。

代码开源：https://github.com/szjmhxd/ahk-scripts

核对数字时，缺的不是「转换」，是「读法」

对账、审合同、看发票的时候，需要在一串数字和它的大写写法之间来回确认。转换工具到处都有，但它们解决的是「输入 1234.56，输出壹仟贰佰叁拾肆元伍角陆分」。

真实场景里数字往往不在这里——它在聊天记录、日志、网页表格、Excel 单元格里。复制出来之后，第一件事是判断这个数到底有多大：是十二亿还是十二万亿？第二件事才是大写。

这两件事其实是同一件事的两面，而现有工具只做后者。

中文数位是四位一级，国际千分位对不上

中文的基本数位是 10、10²、10⁴、10⁸、10¹⁶——相乘关系：十乘十是百，百乘百是万，万乘万是亿。所以中文数字天然是四位一断，不是英文的三位。

1234567890 用两种断法看：

断法 结果 一眼能读出来吗
千分位（3 位） 1,234,567,890 要数逗号：十亿位
万进（4 位） 12,3456,7890 直接是 12 亿

这就是卡片第二行用四位分隔的原因。第一行的单位标注则解决「每一段到底是亿还是万」——数字一长，人是记不住的。

最高一组不写单个单位，直接写它的实际量级：

12,3456,7890 上方是 12亿，扫一眼就知道数量级，不用数位数。位数再多也一样逐段标出来：

大写按财税惯例，用「元」不用「圆」

大写部分不是逐位念，是金额写法：元 / 角 / 分 / 厘。

规则 例子
整数加「整」 1234 → 壹仟贰佰叁拾肆元整
角、分为零但整数有值 1000 → 壹仟元整
角为零、分有值，中间补零 1000.05 → 壹仟元零伍分
分为零、厘有值，同样补零 1234.105 → 壹仟贰佰叁拾肆元壹角零伍厘
金额整数位为零，从最小单位读 0.05 → 伍分，0.005 → 伍厘
小数超过三位，四舍五入到厘 117.21729 → 壹佰壹拾柒元贰角壹分柒厘

三位小数是有对应中文单位的极限（厘），再往下中文里没有通用写法，所以第四位起四舍五入。这一点必须写进界面说明里，否则有人拿它当精确换算用。

实现

整个脚本一个文件，AutoHotkey v2，不需要编译。三个技术点值得展开。

一、触发用剪贴板事件，不挂钩键盘

OnClipboardChange 是系统级事件，只在剪贴板内容变化时回调，脚本读不到任何按键。输入法的算式功能、很多取词工具走的是键盘钩子或选中监听，副作用是它们要知道你敲了什么。

容错分两层：先按纯数字清洗（去千分位、全角符号、元/圆/块/整/% 后缀）；清洗失败时，只有在整段文本里恰好出现一个数字才采用。出现两个以上就不弹——手机号、时间戳、坐标挤在一起的情况太多，猜错比不猜更麻烦。

二、单位标注要压在逗号正上方

9,8765,4321 里的逗号位置不是等距的：数字是比例字体，1 比 0 窄。所以标注位置不能靠字符数乘平均宽度算，必须实测字宽。

分组本身很简单，从右往左每四位切一刀：

marks[].off 是「这个标注对应的位置之前有多少个字符」。渲染时把前缀交给 GDI 量一次宽度，就得到该位置的像素坐标：

LogW 内部就是 GetDC + SelectObject(控件字体) + GetTextExtentPoint32W，量的是控件真正使用的字体，不是估算值。

三、版面得手工摆，AutoSize 排不了层叠

这套「小字压在数字上方同一列」的布局，Gui.Show("AutoSize") 做不出来——AutoSize 只算所有控件的包围盒，不理解层叠关系。做法是全部手工 Move，窗口尺寸也显式给：

控件的文字样式加 +0x200（SS_CENTERIMAGE），让文字在固定高度的控件里垂直居中，字体度量有偏差也不会顶到边。

三个坑

1. GuiCtrl 在这个版本里没有 Destroy()

第一版想每次弹窗都销毁旧标注、重建新的。跑起来直接报：

改成启动时预建 8 个标注控件反复复用，靠 Visible 开关，位置用 Move 改。顺带避免了每弹一次窗就泄漏一批控件。

2. Show 的 x/y 和 w/h 不是一个量纲

这条最容易栽，而且在 100% 缩放的显示器上看不出来：

API 单位
Gui.Show("x.. y..") 物理像素
Gui.Show("w.. h..") 逻辑像素（按 DPI 缩放）
Gui.GetPos() 的 w/h 逻辑像素
GetTextExtentPoint32W 物理像素

在 125% 缩放的机器上实测：Show("w260") 得到 325 物理宽，而 Show("x100") 就是 100 物理坐标。混着用会有两种后果——宽度按缩放倍数偏大（只是留白难看），或者位置、边界判断全错（窗口被钳在主屏）。

正确做法是算一个 SCALE := A_ScreenDPI / 96，所有跨量纲的地方显式换算：

跨屏定位同理，一律走 Win32 的物理像素：GetCursorPos / MonitorFromPoint / GetMonitorInfoW（取 rcWork，扣掉任务栏）。MouseGetPos 的默认基准是活动窗口客户区而不是屏幕，拿它跟显示器坐标比，结果永远落在主屏范围内。

3. 关闭要绑 WM_LBUTTONUP，不是 DOWN

按下就隐藏的话，手指抬起时这个消息会落到浮窗下面那个窗口上——等于顺手在别人的界面里点了一下。绑抬起消息，点下去浮窗还在，抬手时才消失，事件也被自己吃掉。

用法与限制

双击脚本即可运行，托盘图标右键可重载或退出。

操作 效果
复制数字 弹窗，贴光标（无光标时贴鼠标）
点击浮窗任意位置 关闭
Esc 关闭
Ctrl+Alt+N 手动转换剪贴板内容
Ctrl+Alt+M 暂停 / 恢复监听

限制说清楚：

  • 万进分组不符合编程习惯。从屏幕往代码里抄数字时注意别把四位逗号抄成千分位。
  • 小数只能到厘。第四位起四舍五入，末位是近似值。
  • 负数、前导零编号、超过 16 位的整数不显示大写行。007 是编号不是数量，读成「柒元」是错的。
  • 剪贴板里有多个数字时不弹窗。
  • 只处理纯数字文本，2026-11-25 这类带分隔符的日期不会被误认为数字。
